# Decaf CLI delivery audit

Point-in-time record, 2026-10-14. Governing direction:
[coffee-app ADR-019](https://github.com/reedwhetstone/coffee-app/blob/main/notes/decisions/019-decaffeination-is-its-own-catalog-fact.md).

## Purpose and sequence

The catalog must represent decaffeination independently of farm processing. This
is step 2 of ADR-019, following
[Parchment #366](https://github.com/reedwhetstone/parchment-api/pull/366).

Prerequisites verified before consumer work:

- Final migration `20261013210000` was applied successfully, including registered
  post-apply verification and production evidence:
  [apply run](https://github.com/reedwhetstone/parchment-api/actions/runs/38593338579).
- SDK 0.65.0 was published from validated Parchment main `5d2e4b2`, with the same
  tree as the fully validated PR revision:
  [release run](https://github.com/reedwhetstone/parchment-api/actions/runs/38593690506).
- The public npm version and latest endpoints returned 0.65.0; the CLI installed
  that exact lockfile resolution. Registry propagation briefly lagged the
  successful workflow, so no consumer dependency was finalized until installation
  succeeded.

This branch prepares CLI 0.44.0. After merge, publish `v0.44.0` through the existing
release workflow and verify registry availability. Then coffee-app can pin SDK
0.65.0 and published CLI 0.44.0, regenerate its CLI reference, and deliver the
complete reader/control slice. No unpublished package pin or partial application
activation is introduced.

## Changes and invariants

- Search and facets accept strict `--decaf true|false`; omission means any coffee.
  Both exported query functions validate actual booleans from in-process callers.
- `catalog facets decaf` exposes canonical counts. Filtered whole-envelope and
  named facets preserve Parchment values, counts, and access metadata.
- Catalog row and similarity types now derive from the SDK, exposing
  `decaffeinated` and `decafMethod` without maintaining a second domain schema.
  Search, get, and similarity preserve upstream response facts.
- Optional SDK fields are normalized to null only in existing locally derived
  ranking summaries. Missing confidence is not counted as disclosed confidence;
  an unknown price-tier shape is not treated as a numeric price.
- Existing viewer authentication remains unchanged. Parchment decides filter
  access; its 401/403 responses still map to CLI auth failure. No local Member
  check is added that would exclude entitled customer API keys.
- Farm process, decaf detection, similarity classification, scores, historical
  Market Index buckets, and stored brief compatibility stay upstream-owned.
- No catalog data cleanup, brief writes, score recalculation, or legacy bridge
  removal is included. Those remain later ADR-019 steps after app deployment.
- Manifest, help, README, generated context, and compiled package agree. No new
  package export or runtime activation switch is needed.
